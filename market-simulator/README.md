# 长线 · 创投模拟器

## 启动

在项目根目录执行 `./start.sh`，打开 http://127.0.0.1:8790。脚本会在首次运行时创建虚拟环境并安装运行依赖。

仓库已包含 `runtime/universe-v3.json` 和构建所需的匿名清洗数据。缺少运行快照时会从上级目录的 `processed/cleaned/` 自动重建。服务默认仅监听本机，不适合直接公网部署。

Windows PowerShell 可在 `market-simulator` 目录执行：

```powershell
python -m pip install -r requirements.txt
python server.py
```

修改后端后需要重启服务；打开 http://127.0.0.1:8790（投资人端）或 http://127.0.0.1:8790/founder（企业端）。快照读取与生成均显式使用 UTF-8。

## 知识图谱

- 投资人端：打开企业详情，点击“查看知识图谱”。
- 企业端：选择企业后，在侧栏“资料与依据”查看知识图谱、搜索其他企业；在机构详情或接触名单查看投资人图谱。
- 点击节点核对资料与关系来源；选中企业或机构后，点击“以此为中心查看图谱”继续探索。支持返回上一图谱、节点类型筛选、缩放、拖动、适应视图及文字节点列表。浏览图谱不会切换经营企业、修改账户或丢弃融资草稿。

企业图谱包含历史融资轮次、参与机构、通过共同机构连接的其他企业、已收录任职与经营异常记录；机构图谱展示实际参与的融资轮次和被投企业。数据沿用 `universe-v3.json`、机构索引和清洗人员表，无需 Neo4j、外部服务或额外运行依赖。

图谱采用历史快照截止日期，推进模拟日期不会生成新关系。机构参与融资不等于持股或控制；金额为整轮融资额；共同机构不代表两家企业有直接关系。人员记录保留历史或待核验状态，同名人员不跨企业合并；风险来源为按企业、日期及类型汇总的记录。资料缺失时明确提示，单图最多 40 个节点，截断时显示说明。

接口：`GET /api/knowledge-graph?entity_type=company|institution&entity_id=<匿名ID>`，需要新版账户 Cookie。返回 `root_id`、`as_of`、`nodes`、`edges`、`summary`、`truncated` 和 `notes`；节点可含继续浏览的 `entity_id`，边含 `evidence` 来源定位信息。未登录返回 401，参数无效返回 400，实体不存在返回 404。机构参与边按“机构 ID / 轮次 ID”定位索引关联，整轮事件来源保留在融资事件及融资企业关系中。

## 当前规则

融资方案使用研发、招聘、市场和其他用途预算代替材料勾选。预算合计需与目标一致，缺少月净消耗或现金可用期超过 120 个月会返回补充核验；120 个月为界面分析边界，不是市场标准。该规则仅检查方案数值一致性，不等于真实机构尽调。融资开始后的现金基准和币种不可修改，企业现金由交割账本更新。历史已交割记录保留，旧草稿需补预算才能重新评审。

企业端按“发展路径 → 行动工作台 → 资料与依据”组织。历史案例的路径页合并企业概况、历史融资和未来预测；概况按需读取清洗企业主表和主要人员表，展示成立日期、企业类型、地区、资本、匿名法定代表人与任职记录。多条主表值冲突不任意选择；主要人员不等于员工总数，快照不声称实时状态。

发展路径顶部使用横向时间轴：模型读取的全部历史节点按年份汇总，展示每年节点总数及主要事件类型；资料截止点之后单独展示未来预测节点。历史事实、模型预测和用户计划使用不同颜色与标签，预测节点可直接进入行动工作台。自建企业的逐条历史节点及未来预测也采用同一时间轴视觉，但不会把年度汇总替代为模型输入。

企业端入口为 `/founder`，也可从投资端切换。历史案例先看路径，再为预测事件制定行动，完成融资准备并选择目标机构。第三步会将融资方案和机构选择作为情景事件追加到该企业的完整历史路径，重新运行同一模型，展示更新后的未来一年路径及相对原路径新增、保留和不再预测的事件。融资执行仍单独记账，不改写原始企业资料。

企业端默认支持“构建我的企业路径”。企业不需要存在于ESCP中，只填写企业名称，并按“发生日期 → 事件大类 → 具体事件”添加节点。当前标准事件覆盖企业建立、融资、股东、股权与工商、注册资本、核心团队和经营风险；融资阶段、模型事件编号、来源通道、标准语义及相邻事件间隔由系统自动编码。行业和地区仅为可选的相似企业排序信息，不进入未来事件模型。自建路径作为企业自报资料保存在现有账户中，默认不会写回历史数据或训练集。

自建路径预测使用与历史企业相同的FinBERT2、时序编码器和事件集合diffusion。相似企业检索会把候选企业截取到与当前企业相同的企业年龄，只用截取点以前的事件类型、顺序、融资阶段和事件密度计算相似度；完成匹配后才展示候选企业随后12个月的实际历史节点。候选企业必须具备完整的12个月后续观察窗口。这样不会用未来结果参与匹配，也不会把“随后无新记录”解释成经营失败。原“选择案例企业”入口继续保留。

企业端“未来预测”会针对当前企业实际运行保留的最佳事件集合 diffusion。输入按网站资料截止日 2026-03-31 严格截断，包含该企业全部有效日期历史节点；旧训练历史之后的记录使用同一套规范化规则从原始匿名表重建。模型预测随后12个月的融资、企业／机构股东进入、股权结构变更、注册资本变更和注销是否发生及预计月份。现有权重来自历史年度切分验证，把月份解释为截止日后的第1—12个月属于部署外推，尚无未来真实标签验证。结果只用于路径模拟，不参与融资审批、机构匹配、现金、股权或模拟交割；已经注销、没有有效历史或模型环境不可用时明确停止预测。

预测页只突出模型报出的事件，并按预计月份组成未来路径；未报出事件折叠显示。每个节点通向行动工作台，用户可保存状态、计划月份和备注，这些行动计划与不可改写的模型结果分开存储。自建企业也可保存融资准备草稿，但不接入历史案例的真实机构池或模拟交割。页面展示模型实际读取的历史节点数、起止时间和最近输入节点，但不把历史摘要伪装成因果解释。当前事实资料未覆盖预测窗口时统一标为“待观察”。

投资人端按“发现企业 → 我的企业 → 投资账户”组织。“发现企业”合并未来事件线索与历史融资记录；详情先看历史和来源，再看预测与人工跟进，最后决定是否模拟投资。“我的企业”汇总关注、跟进和模拟持仓；“投资账户”汇总组合资金与账户记录。未来机会读取同一版本化预测目录，按五类事件和未来3/6/12个月筛选企业。模型不会自动投资、拒绝或联系企业。创业者在线产生的新预测也会进入同一目录，保证两端对同一家企业显示同一结果。

网站进程通过 `model_forecast.py` 调用常驻的 `scripts/live_model_worker.py`，模型、FinBERT2和规范化历史在首次请求加载，后续企业复用同一进程及语义缓存。默认模型环境为同级研究目录中的 `enterprise_path_sequence/.venv_semantic`；可用 `MODEL_PYTHON`、`ESCP_RESEARCH_ROOT`、`MODEL_DEVICE=cpu|cuda` 和 `MODEL_TIMEOUT_SECONDS` 配置容器。首次构建生成的 `runtime/model-live-history-<截止日>.parquet` 是可重建缓存；原始匿名数据更新后设置 `MODEL_REBUILD_HISTORY=1` 重建。部署镜像必须同时提供最佳权重、FinBERT2本地文件、研究代码和匿名历史数据，不能只复制网站仓库。

投资人机会池需要预先物化。任务可中断续跑，只处理具有有效历史且尚未生成的企业；`--refresh` 会重算已有结果：

```sh
../research/enterprise_path_sequence/.venv_semantic/bin/python scripts/materialize_investor_forecasts.py --batch-size 128
```

产物为 `runtime/investor-forecast-catalog-<截止日>.json`，按截止日和事件定义版本化。运行服务后，新产生的单企业预测也会安全写入该目录。

机构候选来自清洗融资事件的 investor_key_anon，按当前历史快照中可见的来源记录关联；排除来源冲突和同一标识存在多个名称的候选。按同业同阶段企业数、同业企业数排序，展示历史案例与披露日期，不代表实时活跃度、机构真实联系方式或融资成功概率。机构名单和反馈由用户记录，不自动发送消息。

资金缺口 = max(0, 月净现金消耗 × 希望覆盖月数 − 可用现金)，采用用户填写的单一币种、不含新增扩张支出。

企业模拟融资：保存计划（现金、目标、用途、模拟投前估值）→ 向名单机构提交单家申请金额 → 推进一周 → 无同业依据则拒绝、关键材料缺失则补件、否则进入情景条款 → 接受预留额度 → 下一周交割。金额与估值是用户提出的情景条款，不代表真实机构报价，无随机成功率。补件后可重提，条款可拒绝；全部方案处于拒绝或补件状态时可修改目标和估值，旧轮记录归档。

单轮固定价格发行，原股东整体初始设为 100%，交割后原股东比例 = 投前估值 /（投前估值 + 本轮累计到账），机构比例 = 本机构到账 / 同一分母。支持同轮多机构、额度预留、超募检查与重复交割保护；企业现金独立于投资账户。推进周仅处理融资，不模拟经营收支。真实估值模型、真实股权结构以及连续多轮融资尚未实现。

- 历史快照截止 2026-03-31。网站企业池先排除截止日前已经注销或撤销的主体，再沿用预测数据的 `clean_v1` 历史门槛：截至观察日至少3个不同事件月份，且首末事件跨度至少6个月；只根据过去历史筛选，不根据未来标签、是否融资或预测结果删企业。具体保留规模以构建产物统计为准。
- 支持行业、融资阶段和风险筛选，企业完整历史按需加载。
- 模拟投资扣除现金、增加投入成本，保留逐笔结果。缺失金额不补固定默认值，币种不自动换算。
- 资金图展示现金与投入成本，新账户保留开户基准，旧账户不补造缺失历史。
- 成本不等于市值。目前没有可靠股权定价、退出或收益模型；推进月份只推进日期和按账户设置计提费用，不产生随机收益。

## 代码与存档

- `server.py`：服务、SQLite 存档及并发版本校验。
- `knowledge_graph.py`：历史关系索引、来源与图谱规模限制；`web/knowledge-graph.js` / `.css` 为两端共用组件。
- `model_forecast.py`：网站与常驻模型进程之间的鉴权后推理桥接、超时及企业级结果缓存。
- `forecast_catalog.py`：投资人机会池的版本化预测目录、事件/时间筛选和覆盖率。
- `forecast_workflow.py`：企业行动计划、投资人关注和跟进记录，保存在现有账户 JSON 中。
- `custom_path.py`：企业自建路径的标准事件分类及模型字段映射。
- `cohort_filter.py`：按 `clean_v1` 的过去历史门槛筛选可进入模型与网站企业池的企业，并输出清洗审计规模。
- `financing_scenario.py`：把融资方案、机构选择和后续融资进展转换为带日期的情景事件，用于重新生成未来路径。
- `../scripts/live_model_worker.py`：完整历史构造、FinBERT2编码、最佳 diffusion 权重加载与未来12个月推理。
- `../scripts/materialize_investor_forecasts.py`：批量、可续跑的机会池预测生成任务。
- `evidence_engine.py`：生产操作规则。
- `engine.py`：共享账户、记账与查询；已移除停用的随机估值和旧交易分支。
- `data_pipeline.py`、`build_forward.py`：数据构建。
- `web/`：当前页面；`forecast-ui.js` 在投资人端复用企业详情并提供机会池交互，JS 文件有加载顺序依赖，不能单独删除。
- `runtime/saves.sqlite3`：账户存档，不可作为缓存清理。
- `runtime/universe*.json`：数据快照，旧版本保留用于追溯。

备份前停止服务，再复制完整 runtime 目录。建立新账户切换浏览器账户，不删除原存档。

## 验证

```sh
.venv/bin/python -m pip install -r test-requirements.txt
.venv/bin/python -m unittest test_evidence -v
.venv/bin/python -m unittest test_founder -v
.venv/bin/python -m unittest test_model_forecast test_forecast_workflow -v
# 先启动网站，浏览器测试需要 Playwright 和 macOS Chrome
.venv/bin/python test_revision_browser.py
.venv/bin/python test_founder_browser.py
.venv/bin/python test_contacts_browser.py
```

覆盖缺失值、币种、资金记账、旧记录保护、详情加载、投资结果、开户基准、刷新恢复和手机布局。旧认购、意向和旧图表测试已移至仓库外备份，不作为当前验收标准。

知识图谱验证（Windows 示例）：

```powershell
python -m unittest test_knowledge_graph test_evidence test_founder test_financing test_institutions -v
python -m unittest test_model_forecast -v
python -m pip install -r test-requirements.txt
python test_knowledge_graph_browser.py --channel msedge
```

浏览器测试自动启动临时本机服务并使用独立临时数据库，不改动真实账户。可用 `--channel chrome` 指定 Chrome，或在安装 Playwright Chromium 后省略非 Windows 平台的 channel；`--output <目录>` 保存桌面和手机截图。覆盖接口参数与账户检查、两端入口、关系来源、节点跳转、错误重试、快速切换、输入保留及手机布局。
